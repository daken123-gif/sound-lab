## 現在の問い

Loopy Pro研究で録音済みループへ直接触れる構造を考えたとき、Dedalusをどのような参照として使っていたか。その時間処理の核を、現在の4トラック／Skulptur中心のField Looperへどう接続し、何を採用しないか。

## 研究の由来と権威

ユーザーの現在発話:

> loopy研究でdedalusを参考にしていました

この発話を、この研究の由来に関する現行権威とする。

- Dedalus研究は、Loopy研究と無関係に後から追加された独立エフェクト研究ではない。
- Loopy研究における「録音したループを合成し、その実波形へ触れて演奏する」構想を時間方向へ発展させる参照としてDedalusを扱う。
- 当時の3ループ案は、統合判断 `D-001` の4トラック化で失効している。
- 当時のKAOSS型マスターFX案は、`D-007` と `D-008` で失効している。
- Dedalusを新しいマスターFXまたは第五のルーパーとして復活させない。

## 観測できた事実

### 可変ディレイネットワーク

- Dedalusは複数の可変ディレイラインへ入力を通す。
- 各ラインの遅延時間は最小値と最大値の間で変化する。
- 遅延時間はFree（ms）、Sync（音価）、Pitch（周波数周期）で指定できる。
- Pitchでは、たとえば440 Hzを `1 / 440` 秒の遅延周期として扱い、フィードバックによって櫛形共鳴を作る。

### Granulationの意味

- 各ディレイラインには二つの読取りヘッドがある。
- 二つのヘッドをGrainFreqに従ってクロスフェードする。
- Scrubは最短遅延と最長遅延の間を走査し、各切替時点の読取り位置を決める。
- RandはScrubの運動を正弦的な往復からランダム運動へ変える。
- このgranulationは、サンプルを多数の独立粒へ分解して再配置する一般的なグラニュラーサンプラーとは役割が違う。遅延時間変更時の不連続とピッチ変化を抑えながら、過去の読取り位置を切り替えるための機構である。
- Glideを有効にすると離散切替を迂回して遅延時間を連続変化させ、ピッチの滑りを発生させる。

### 循環内部

- Feedbackはディレイ出力を再入力する。1を超える値では持続的なフィードバックが起こりうる。
- FilterCut1 / FilterCut2はフィードバック循環内の通過帯域を制限する。
- OverdriveとColorは歪み量と歪ませる帯域傾向を変える。
- Crossは左右のディレイ回路を交換し、RndPanは粒をステレオ空間へ散らす。
- Duck / Gateは入力レベルを基準にウェット信号またはフィードバックを抑制する。

### モジュレーション

- デスクトップ版には8個のモジュレーターがある。
- Draw、Chaos、Stepの各生成方法を持つ。
- パラメータだけでなく、他モジュレーターや自分自身も変調できる。

## 推論・設計仮説

### Dedalusの本質

Dedalusから採るべきものは「グリッチ音色のプリセット」ではない。

```text
過去の読取り位置を選ぶ
  -> 二つのヘッドで切替ノイズを抑える
  -> フィードバック内で帯域と歪みを変える
  -> 現在の音へ戻す
```

この循環によって、録音された時間を固定波形ではなく、再び演奏できる音響物体へ変える。

### Loopy研究との接続

Loopy側の責務:

- 4トラックのRAW音声を保持する。
- 録音、再生、停止、消去、長さ、現在位置を明示する。
- ループの状態を勝手に変えない。

Dedalus側の責務:

- Loopyが保持した素材から、過去の一部分を時間メモリへ送る。
- その断片を反復、拡散、共鳴、減衰させる。
- 処理結果を元トラックへ破壊的に書き戻さない。

Skulptur側の責務:

- ドライ音とDedalus帰還音を含む現在の合成波形へ直接触れる。
- 録音後の主演奏面であり続ける。

### 現在の信号構造候補

```text
4トラックRAW
  ├─ dry ─────────────────────┐
  └─ 明示send -> Dedalus共有時間メモリ ─┤
                                       v
                             合成された実波形
                                       v
                              Skulptur型主演奏面
                                       v
                             Performance Take / 出力
```

- Dedalusは4トラックへ一基ずつ挿さない。
- 共有時間メモリを一基だけ置く。
- 送信元は選択トラック、または明示的に選んだ複数トラックとする。
- RAWは常に別経路で保持する。
- Dedalusの処理順をSkulpturの前後どちらに固定するかは、聴取試験前には決めない。

## Field Looperへ採用する点

1. 二読取りヘッドと等電力クロスフェードによる可変遅延
2. 最短／最長遅延範囲を走査するScrub
3. 規則運動からランダム運動までを連続化するDrift
4. フィードバック循環内の帯域制限
5. 循環内のソフトクリップ／サチュレーション
6. 遅延周期を音程へ合わせる共鳴モード
7. 入力に反応するDuck / Gate
8. 単一の共有時間メモリ
9. ドライRAWを壊さないsend / return構造

## 採用しない点

- Dedalus内蔵サンプラーを別の録音系として複製しない。
- 8モジュレーターを編集する独立ページを作らない。
- モジュレーター間の再帰配線をユーザーへ操作させない。
- ファイル管理、プリセット管理、MIDI設定を主演奏面へ出さない。
- Preset Morphing PadをKAOSS型XY面として復活させない。
- 4トラックへ4インスタンスを常設しない。
- Dedalusを第五トラックまたは独立ルーパーと呼ばない。
- Dedalusの元UIを模倣しない。

## 操作仮説

新しいノブ画面を追加するのではなく、合成波形に対する少数の直接操作へ圧縮する。

- 波形上の時間位置を触る: どの過去断片を送るか
- 横方向の移動量: 読取り位置／時間の古さ
- 縦方向の移動量: 循環量／減衰時間
- 短い払い: 断片を時間メモリへ送る
- 再接触: 循環中の断片をSkulptur側の操作へ戻す

この割当は研究仮説であり、UI採用済みではない。深いモード、同時押し、常設ノブを増やさず実機テストで比較する。

## DSP実装候補

公式内部構造の再現ではなく、このプロジェクト用の候補である。

```text
input send
  -> 入力ゲート／duck検出
  -> 共有循環バッファ
  -> 複数の可変ディレイ読取り
       - 各ライン二ヘッド
       - 等電力クロスフェード
       - 補間読取り
  -> 直交フィードバック行列
  -> HP / LPまたは帯域制限
  -> DC blocker
  -> soft clip
  -> wet return
```

候補制約:

- ディレイライン数は4本から測定を始めるが、4トラックとの一対一対応ではない。
- フィードバック行列はエネルギーを急増させにくい直交行列を候補にする。
- 係数変更はサンプル単位で平滑化し、zipper noiseを避ける。
- ディレイ時間の跳躍は二ヘッドのクロスフェード、Glide時は補間読取りで処理する。
- フィードバック1以上を許す場合も、循環内フィルター、soft clip、出力リミッターを外さない。
- CPU品質段階を設ける前に、iPhone 13 mini相当実機で必要な最低品質を測る。

## 失効した判断

1. 3ループ前提 — `D-001` の4トラック化で失効。
2. KAOSSをマスター演奏面にする — `D-003` は `D-007` / `D-008` により失効。
3. Dedalusを別ルーパーとして追加する — 現在はLoopy由来の共有時間メモリとして扱う。
4. Dedalusを4トラック後段へ常時直列挿入する — RAW保持と明示sendの原則に反するため採用しない。
5. 強制横画面 — `D-009` により失効。縦横は実機検証まで固定しない。

## 検証計画

### DSP単体

- インパルスを入力し、遅延時刻、フィードバック減衰、左右交差を測る。
- 正弦波を入力し、Pitchモードの共鳴周波数と誤差を測る。
- 遅延時間を跳躍させ、クリック、振幅穴、意図しないピッチ変化を記録する。

- 打撃音とドラムループ

## 現在の判断

Dedalusは採用済み機能ではなく、`active` な研究である。

Loopy研究から受け継ぐのは、録音済みループを時間方向へ再び演奏可能にする問いである。Dedalusからは、その問いに対する二読取りヘッド、Scrub、フィードバック循環、共鳴化を抽出する。4トラック、RAW保持、Skulptur主演奏面を置き換えず、その間を接続する共有時間メモリとして検証する。
