## 今回の修正

前案の `anchor / node / cluster / bridge` は、接触数が増えても関係数を線形に保つ点では有効だった。しかし、追加nodeを追加声部または追加周期へ直結すると、結局「一本の指＝一つの音楽的役割」へ戻ってしまう。

Charlie Hunter研究は、指を対等な独立奏者としてではなく、低音・上声・ミュート・共有ポケットを分担する一つのチームとして扱う。したがって、五接触を受理できることと、五声を鳴らすことは分けなければならない。

ここでノンミュージシャン向けに減らすべきなのは、演奏判断の数ではなく、**一回の接触が何を引き受けているかを見失う経路**である。

## 三つの責任層

接触を声部へ割り当てる代わりに、演奏中の責任を三層へ分ける。

### 1. `FLOOR` — いま何が成立しているか

- 共有clock候補
- 聞こえているvoiceと、現在休止中だが戻れるvoice
- voice間のcoupling
- 局所的な前後差、音価、密度
- dryとtailの区別

`FLOOR`は自動伴奏ではない。現在までの接触で成立し、別の接触が入っても完全には消えない演奏上の足場である。

### 2. `CLAIM` — いま何を変えているか

各接触は固定役割ではなく、現在対象への一時的なclaimを持つ。

```text
CLAIM {
  target: node | edge | floor | memory
  action: form | hold | deform | cut | return
  contactIds[]
  startTime
  audibleConsequence
}
```

複数の接触が一つのclaimを共同で担ってよい。二本の指が二声を意味する必要はなく、二点間距離が一つのedgeの位相差または音価を変えてもよい。逆に一本の移動が、共有ポケットを保ちながら低音と上声へ異なる結果を与えてもよい。

### 3. `MEMORY` — 過去の演奏から何を戻せるか

- 直前に自分で作った短い断片
- CUT後も残る不在voiceの位置
- tailとその終了条件
- 以前成立したrelation state

Madlib接続が要求するのは、既成loopの選択ではなく、演奏者自身の直前の出来事を素材庫として掘り直すことだ。ただし保存と再投入は別claimにする。システムが自動で「良い断片」を選んで完成展開を作らない。

## 因果エネルギーの修正

既存の `causalEnergy` を、指の移動量や経過時間だけで減る値にすると、静止、長い音価、休止、聴く時間を操作不足として罰する。これはHunterの休止、Millsの待機、Aphex Twin研究の低密度保持と衝突する。

そこでenergyは「触り続けた量」ではなく、**接触後に新しい出来事を自走生成できる有限予算**へ限定する。

```text
event_budget_next
  = clamp(
      event_budget_now
      + explicit_performed_change
      - generated_event_cost
      - released_tail_cost,
      0,
      safe_max
    )
```

- 静止して保持するだけなら、予算を大きく消費しない。
- 無音の保持はeventを生成しないので、ゼロ予算でも成立できる。
- 指を離した後のtailや反復は、生成する出来事ごとに有限予算を消費する。
- 予算が尽きた後も、`MEMORY`として関係は残せるが、完成伴奏は鳴り続けない。
- 音量と予算は分離する。大きな音ほど長く続く設計にしない。

これにより「動き続けなければ演奏にならない」と「一度触れば完成loopが続く」の両方を避ける。

## 最小操作文法

| 操作 | 演奏者が決めること | システムが補助してよいこと |
| --- | --- | --- |
| `form` | 新しい音、clock、relationを成立させる | 音量安全境界、表示上の対象解決 |
| `hold` | 音価、休止、関係を現在形で保つ | 微小な指ぶれの平滑化 |
| `deform` | 位相、間隔、密度、couplingを変える | 可聴範囲への制限と連続補間 |
| `cut` | 対象だけを消し、何を残すか決める | クリックノイズ防止、有限tail |
| `return` | loop頭でなく現在のpocketへ戻す | 現在clock候補の表示、一時lock |

初回利用者へ必要なのは五語の暗記ではない。同じ対象が、触れる、保つ、動かす、払う、戻すという短い身体差で変わり、結果が画面と音の両方から追えることだ。

## ノンミュージシャンの再定義

今回の接続で、ノンミュージシャンを「少ない操作しかできない人」と扱う定義は失効する。

ノンミュージシャンとは、既成奏法や楽典を先に所有していなくても、現在の音へclaimを持ち、結果を聴いて次のclaimを変えられる演奏主体である。楽器の役割は成功を保証することではなく、次を成立させることにある。

1. 何が自分の操作で起きたか分かる。
2. 何を保ち、何を変え、何を消したか分かる。
3. 失敗を全消去せず、残った床から回復できる。
4. 休止や静止を、演奏していない状態へ勝手に降格されない。
5. 反復を使っても、再生と現在の介入が区別される。

## 失効・修正する前案

- 「追加nodeは独立声部を一声追加する」を一般規則にしない。
- 「三つ目以降のnodeは独立周期を一つずつ追加する」を一般規則にしない。
- 接触数が多いほど表現力が高いとは判定しない。
- `causalEnergy`を常時の微小運動や単純な経過時間で補給・減衰させない。
- releaseを必ず発音終了とせず、有限tail、記憶、現在pocketへのreturnを分ける。

anchor / node / edge / cluster / bridge自体は失効させない。幾何学的な関係表現として残すが、音楽的役割は `CLAIM` が決める。

## 次の構造テスト

1. 一接触で `form -> hold -> cut` を行い、hold中の静止が追加eventを生まないこと。
2. 三接触を一つのteam claimとして使い、三声へ自動展開しないこと。
3. 五接触で二つのclaimを同時保持し、接触数とclaim数が一致しなくても追跡できること。
4. edgeの位相を崩して `BROKEN` に入り、自動undoなしで別の `FLOOR` を作れること。
5. release後のevent budgetが有限回のtail／反復で尽きること。
6. 静止、休止、低密度の十秒間を、入力欠落や失敗として誤判定しないこと。
7. `MEMORY`から戻す断片が、既製素材でなく同じTake内の演奏由来であることを追跡できること。

これは研究上の修正であり、既存simulation-v0、製品schema、DSP、UIへはまだ反映していない。
