# Battles研究 — 反復を固定物ではなく演奏状態にする

- **research-id:** `20260903-battles`
- **status:** `active`
- **研究対象:** Battles
- **現在の問い:** 既存ループの垂れ流しを避け、短い素材、身体的な演奏、機械的反復をリアルタイムの即興楽器へどう接続できるか
- **更新日時:** 2026-09-03 UTC

## 0. 研究境界

本記録は、Battlesを「複雑拍子のロックバンド」または機材リストへ縮めず、次の三者関係として読む。

1. John Stanierの身体が維持する強い周期
2. Ian Williamsらが生成・再サンプリングする短い反復
3. ループの内部状態を変える切替、開始点移動、積層、切断

確認できた一次資料・公式カタログ、本人インタビュー、Shazam経由のApple Music公式30秒プレビューを使用した。プレビュー分析は全曲分析ではない。プレビュー位置も曲ごとに異なるため、曲全体の形式、正確な拍子、BPMを確定する証拠には使わない。

## 1. 資料から確認できた事実

### 1.1 編成と作品系列

Warpの現行アーティストページはBattlesをIan WilliamsとJohn Stanierが率いるユニットとして記載している。Warp公式カタログで確認できる主要作は次の通り。

| 年 | 作品 | 研究上の位置 |
|---:|---|---|
| 2006 | *EP C/B EP* | 初期EP群。短い単音ループと精密なドラムの接続 |
| 2007 | *Mirrored* | 4人編成。加工声、生演奏、ループを一つのバンド音響へ統合 |
| 2011 | *Gloss Drop* | 3人編成。複数の客演声を曲ごとの異物として接続 |
| 2015 | *La Di Da Di* | 3人編成。器楽、反復、音色、構造変化を前面化 |
| 2019 | *Juice B Crypts* | 2人編成。生演奏と編集・再サンプリングの再編 |
| 2020 | *Juice B Mixed* | 公式リミックス展開 |

### 1.2 Ian Williamsのループ手法

Abletonの本人インタビューで確認できる要点:

- WilliamsはDon Caballero時代、もう一人のギタリストが脱退した後、Akai Headrushを使い始めた。
- Battles初期の発想は、厚い和音ではなく単音を刻む簡素なループだった。
- その簡素さが、Stanierのミニマルで明瞭なドラムと対応した。
- ペダルからAbleton Liveへ移り、ループをさらに別ループへ録り直す反復的な再サンプリングを使うようになった。
- 同一の音声ループを三つのトラック／クリップへ複製し、それぞれの開始点を少し変えて切り替える。Williams自身はDJのbeat jugglingに近い方法として説明している。
- ソフトウェアやPushを、既存の運指習慣を崩し、予想しなかった状況を作るためにも使っている。
- 一方で、PC中心の演奏は演奏者と観客の距離を生む問題もあると本人が認めている。

ここでは、ループは完成済み伴奏ではない。短い素材を複製し、異なる読取位置を持つ複数の状態へ分け、演奏中に切り替える対象である。

### 1.3 John Stanierの制約設計

Modern Drummerの本人インタビューでは、高い位置のクラッシュについて次が確認できる。

- 当初はハイハット以外のシンバルを使いたくなかった。
- クラッシュを手元に置くと使い過ぎるため、意図的に届きにくい高さへ置いた。
- その一打を大きな区切り、本人のいう「master reset button」として使う。

これは見た目だけの特徴ではない。物理的にコストの高い操作を作ることで、頻度と意味を結び付けている。

### 1.4 公式リミックス資料

BattlesとWarpは*Juice B Crypts*の素材を、シンセ、旋律、ドラム等へ分解して公開した。素材は地下鉄路線図を模した接続図に割り当てられ、一地点に最大5素材が積層された。

この公開形態は、曲を一本の完成済みタイムラインとしてではなく、素材が複数の経路で接続されたネットワークとして示している。

### 2.3 観測から言える範囲

- `Atlas`のプレビューでは、0.44秒から7.11秒までほぼ倍化関係を含む包絡周期が現れた。単一周期の上に複数階層の区切りを作る分析候補になる。
- `Tonto`では約1.97秒と3.95秒が強く対応し、短い周期と長いまとまりの階層が見える。
- `The Yabba`は約1.09〜1.51秒へ近接した複数候補が現れ、単一の明瞭なRMS周期だけへ還元しにくい。
- `A Loop So Nice...`は0.35〜1.09秒の短周期群と高いスペクトル重心を示し、短い明るい素材を細かく組み替える区間の分析候補になる。
- `Ambulance`、`Dot Net`、`Futura`はプレビュー内のRMSコントラストが比較的大きく、反復を維持しながら振幅状態を切り替える研究対象になる。

これらは30秒区間の信号観測であり、作曲意図、全曲の拍節構造、実演時の操作を直接証明しない。

## 3. Battlesの作曲構造に関する推論

以下は資料と限定音源観測からの推論であり、本人がそのまま述べた事実ではない。

### 3.1 「複雑さ」は素材数ではなく読取差から生まれる

同じ素材を三つに複製し、開始点だけを変える手法では、音源の種類は増えていない。それでもアクセント位置と周期の知覚は変わる。

したがってBattlesから採るべきものは「多数のループを重ねること」ではなく、**一つの素材へ複数の時間的な読取状態を与えること**である。

### 3.2 ドラムとループは主従ではなく異なる時間を担当する

Stanierのドラムはクリックの代用品ではない。反復に身体的な重量、押し引き、区切りを与える。一方、ループは人間が一度弾いた断片を固定・複製・再配置して、身体だけでは維持しにくい局所周期を作る。

- ドラム: 現在時刻を身体で押す
- ループ: 過去の演奏断片を現在へ戻す
- 再サンプリング: 複数の過去を新しい現在として固定する
- reset/choke: 蓄積した過去を切り、演奏者を現在へ戻す

### 3.3 曲の展開は「追加」だけではない

ルーパー演奏が陥りやすい、録音→追加→追加→全消去という一方向の密度上昇を避けるには、次が必要になる。

- 同一素材の状態交替
- 既存レイヤーの一時的な不在
- 読取開始点のジャンプ
- 周期長の瞬間的な変更
- tailだけを残す切断
- 一打または一操作による全体reset

## 4. 現在のプロジェクトとの接続

### 4.1 4トラックへ直結しない

4トラックはRAW録音を保持する中心構造である。Battlesの三クリップ技法を、そのまま3本の録音トラック消費として実装すると、原音保護と操作の単純さを壊す。

候補構造:

```text
4 RAW tracks
  -> selected source / mixed source
  -> one temporary capture
  -> three read heads
       A: base start
       B: offset start
       C: alternate length or reverse candidate
  -> live state switching
  -> optional re-capture
```

三つのread headは三つの新規トラックではない。同一バッファへ異なる読取状態を与える一基の演奏器として扱う。

### 4.2 Skulpturとの接続

Skulptur型主演奏面は録音素材のスペクトルを身体で変形する。Battles型の読取状態は、その前段または内部の時間軸として候補になる。

- 1本指: 現在のread headを連続変形
- 2本指: A/B状態間の距離または切替境界
- 3本指: 一時capture / re-capture。常時操作にはしない
- 離す: 自動録音ではなく、直前状態へ戻すかtailを残すかを明示契約する

ただし、既存の`x -> 10 bands`、`y -> Cut / Neutral / Feedback`へ無断で別機能を上書きしてはならない。時間操作を同じ面へ載せる場合は、接触数、押下開始位置、明示モードのどれがownershipを持つかを別研究で検証する。

### 4.3 独立DRUMSとの接続

Battlesを根拠に、ドラムを4トラックへ吸収しない。現行方針どおり独立演奏系を維持する。

研究候補は「ドラムをマスタークロックにする」ことではなく、次の二方向同期である。

1. ドラムのオンセットから、ループ状態切替の候補時点を提示する
2. ループの周期境界をドラムへ強制せず、演奏者がreset/chokeで再接続する

自動追従を強くすると、Stanierの身体と固定ループの緊張ではなく、単なるquantizeになる。

### 4.4 Autechre / Aphex Twin / Jeff Mills / Charlie Hunterとの接続

| 研究 | Battlesとの接点 | 混同しない点 |
|---|---|---|
| Autechre | 状態遷移、生成規則、周期の内部変形 | Battlesには生ドラムとライブバンドの身体的基準が強く残る |
| Aphex Twin | 同一素材の編集、start point、細分化 | Battlesは編集結果を舞台上の再現・演奏へ戻す |
| Jeff Mills | 明示的な切替、即時判断、resetの強さ | デッキ／マシンの交換文法をそのまま移植しない |
| Charlie Hunter | 一人の身体が複数の役割を同時保持 | 多声部の技能模倣ではなく、役割を接触へ配分する |

Battlesはこの四研究の中間にある。生成・編集された複雑さを、身体で制御可能な少数の演奏行為へ戻すための参照になる。

## 5. 採用候補

現段階で研究候補として残す。製品採用ではない。

1. **同一素材・三読取状態**
   - A/B/Cは別音源ではなく、同一captureの異なる開始点と長さ。
2. **状態切替を演奏にする**
   - 波形編集画面で数値を設定するのではなく、触れている間に状態を往復できるようにする。
3. **re-capture**
   - 現在鳴っている合成結果を一時的に再取得し、次の読取対象にする。
4. **高コストreset**
   - 誤操作しにくく、演奏上の大きな区切りになる単一操作。
5. **減算可能なループ演奏**
   - 追加だけでなく、一時不在、choke、元素材への帰還を同格にする。
6. **画面を見続けなくても因果が分かるフィードバック**
   - PC操作の距離化というWilliams自身の問題意識に対応し、接触、音、波形の因果を同じframe列から出す。

## 6. 採用しない点

- Battles風のプリセット音色
- 「マスロック」らしい変拍子の自動生成
- 4トラックを三つの複製クリップで消費する構成
- 演奏者の代わりに複雑さを自動生成するブラックボックス
- 深いクリップランチャー画面
- ノート単位の細密編集を主演奏UIへ持ち込むこと
- ドラムを機械的なグリッドへ完全同期すること
- 高いクラッシュシンバルの外見だけをUI演出として模倣すること

## 9. 失効した判断

- 「Battlesの中心はポリリズムである」という単独説明は失効。ポリリズムは結果の一部であり、研究の中心は短い素材の複数読取、身体的周期、状態切替の関係に置く。
- 「4本の異なるループを重ねればBattles型になる」という設計は失効。同一素材から複数の時間状態を作ることを先に検証する。
- 「ドラムをマスタークロックへ固定すればよい」という設計は不採用。身体と機械の緊張をquantizeで消さない。
