# Teenage Engineering製品研究 — 4トラック Field Looper

- research-id: `20260828-teenage-engineering`
- 対象: iPhone向け4トラック録音・ループ・演奏アプリ
- 状態: 研究記録／設計判断（実装未着手）
- 更新: 2026-08-28

## 現在の問い

Teenage Engineering製品に共通する「録る・時間を掴む・一時的に演奏する・必要な結果だけ残す」という操作文法を、4トラックのiPhoneアプリへどう移植するか。

## 記録の境界

この文書では、公式資料で確認できた製品挙動、そこから導いた設計推論、ユーザーとの会話で採用された判断を分離する。製品名や機能名が一致していても、アプリ案の挙動はTeenage Engineering製品そのものの仕様ではない。

## ユーザー判断／現在の設計Canon

- 音声素材は4トラックとする。
- 録音は必ずユーザーが`REC`を押して開始する。常時録音・自動録音は採用しない。
- 4トラックは共通時間軸を持つ。
- 4本を合成表示した波形を、時間操作の演奏面として直接触れる。
- 元録音は非破壊で保持する。
- KAOSS型操作は合成後のマスターFXとして扱う。
- 一時的な波形操作と、記録される`PERFORMANCE TAKE`を明確に分ける。
- iPhoneの実入力経路、モニター状態、録音可能状態、実録音状態を分離表示する。

## 一次資料から確認した事実

### OP–1 field

- Tapeには4本のステレオトラックがあり、共通のテープ時間を扱う。
- Lift／Drop／Split、Lift All、Merge Dropなどのテープ編集がある。
- Tape TricksにはLoop、Break、Reverse、Chop、Memoなどがある。
- 入力画面では入力元、入力ゲイン、録音閾値を選択できる。
- Sound Pathでは信号経路を確認でき、重要な値がゼロの場合は警告される。
- 公式更新履歴では、1.7.0でTape Undo、1.6.0でLift／Drop後のクロスフェードが追加されている。ループのポップ音や位置ずれに関する修正も記録されている。

### OP–XY

- Punch-in FXは押している間のライブ演奏として使える。
- 録音中のPunch-in FX操作は専用のPunch-inトラックへ記録できる。

### EP–133 K.O. II

- Loop機能では保持操作でループを作り、位置や長さをリアルタイムに変更できる。
- ループ位置の移動はテンポに同期する。
- フェーダー操作は`REC`との組み合わせで記録される。

### OB–4

- 入力と再生の操作からループを作り、位置をテンポ同期で移動できる。
- Beat Matchには自動とRAWの考え方がある。
- 本体は直近の音声を常時保持するが、このアプリ案では採用しない。

### TP–7

- モーター駆動リールは録音の視覚フィードバックと、停止・スクラブ・スクラッチ操作を兼ねる。
- 録音状態は赤い表示とリールの動きで重複して示される。

### TX–6

- メインとCueを分け、チャンネルごとの入力処理とミックス処理を整理している。
- iOS機器との接続を想定した使用経路がある。

### PO–35 speak／PO–33 K.O!

- PO–35は録音した声をキャラクター変更し、演奏・シーケンス化できる。
- PO–33は録音素材をメロディ素材またはドラム素材として扱う。

## 観察から導いた設計推論

| 横断して見える型 | 4トラックアプリへの翻訳 |
|---|---|
| 指で一時的に試す | 波形GRAB、逆再生、ループ長、KAOSS操作は指を離すと解除 |
| 明示的に記録する | `REC`中のみ`PERFORMANCE TAKE`へ操作を記録 |
| 時間を直接触る | 合成波形で位置、範囲、スクラブ、反復を扱う |
| 素材と演奏結果を分ける | 4本の元音声を保護し、操作イベントを別レイヤー化 |
| 状態を物理的に重複表示する | RECボタン、対象トラック、波形位置の3箇所で録音を表示 |
| モードごとに役割を限定する | `TAPE`は時間操作、`FX`はKAOSS操作とし、同じジェスチャーを衝突させない |

## 採用する設計

### 4トラックと共通時間軸

4本の音声トラックは同じ時間軸を共有する。合成波形はミックス済みファイルではなく、4本を束ねて時間を操作するビューである。個別波形は素材編集、合成波形は演奏、KAOSSはマスター処理という責務に分ける。

### PLAY AS

初期状態は4トラックすべて`TAPE`。録音後に必要なトラックだけ再生方式を切り替える。

| モード | 録音の扱い | 主操作 |
|---|---|---|
| TAPE | そのままループ再生 | START / END / SPEED / DIRECTION |
| KEYS | 音階を付けて演奏 | ROOT / RANGE / ENVELOPE / FILTER |
| SLICE | 自動分割してパッド演奏 | CHOPS / OFFSET / ENVELOPE / PITCH |
| VOICE | 声を再合成 | PITCH / FORMANT / START / SPEED |

`VOICE`の初期値はNeutralとし、話者の輪郭を保つ。Robot、Noise、Vocoder、Synth系は明示選択された場合だけ使う。

### 合成波形の演奏

| ジェスチャー | 結果 |
|---|---|
| 1本指で触れ続ける | GRAB／一時反復 |
| 左右へ動かす | ループ位置を滑らせる |
| 上へ動かす | ループを短くする |
| 下へ動かす | ループを長くする |
| 2本目の指を置く | 逆再生 |
| 全指を離す | 通常再生位置へ復帰 |

ループ長は`1 BAR → 1/2 → 1/4 → 1/8 → 1/16 → GRAIN`の段階式とする。GRAINも録音素材の一部分を反復するだけで、入力がなければ鳴らない。

### AUTOとRAW

- `AUTO`: 拍を取得できた録音。着地点とループ長を拍へ吸着する。
- `RAW`: 声、環境音、不定形演奏。波形上の実時間をそのまま操作する。
- 録音音声自体を自動で切断・伸縮・補正しない。
- 拍検出に失敗しても録音と再生を止めない。

### PERFORMANCE TAKE

これは第5音声トラックではなく、以下の操作イベントを持つ非破壊レイヤーである。

- GRAB開始・終了
- ループ位置
- ループ長
- 正転／逆転
- KAOSSのX／Y
- FXプリセット切替

通常操作は指を離すと消え、`REC`中の操作だけ記録される。記録は合成波形上の細い赤線として表示し、操作単位でMute／Deleteできる。4本の音声は変更しない。

### 入力・モニター・録音状態

上部に実経路を常時表示する。

`iPHONE MIC → PRE → T1 → MASTER → OUTPUT`

| 表示 | 意味 |
|---|---|
| INPUT ON/OFF | 入力が接続されているか |
| MON ON/OFF | 入力音を出力へ返すか |
| REC READY | 選択トラックへ録音可能か |
| REC | 実際に録音中か |

`INPUT OFF`では無音録音を開始しない。`MON OFF`でも録音は可能とする。

### 編集

個別トラックには`SPLIT / LIFT / DROP / UNDO`だけを置く。切断・配置点には短いマイクロクロスフェードを自動適用する。4本を1本へ焼くMergeは常用せず、元を残す`BOUNCE COPY`として、空きトラックがある場合だけ利用可能にする。

## 採用しないもの

- OB–4型の常時ローリング録音
- 入力検出による自動REC
- 拍検出失敗による録音停止
- 元録音へ自動的にピッチ補正・タイムストレッチを焼き込むこと
- KAOSS操作の自動記録
- 4本を破壊的に1本へ統合する常用Merge
- `VOICE`初期状態でのRobot／Noise化

## 原文1 — 声を楽器へ変える設計

今回は「録音した声を、ノイズではなく楽器に変える方法」が見えました。

PO–35 speakの核心は、エフェクトを増やすことではありません。録音された声を次の4要素へ分離して扱うことです。

| 要素 | 音楽的な意味 |
|---|---|
| Pitch | 音程 |
| Formant | 声質・話者らしさ |
| Start | 発音位置 |
| Speed | 時間・リズム |

PO–35は声を録音し、キャラクター変更、演奏、シーケンス化まで一続きにしています。[PO–35公式ガイド](https://teenage.engineering/guides/po-35/en)、[PO Metal公式](https://teenage.engineering/products/po/metal)

一方、PO–33 K.O!では、同じ録音でも「メロディ音源」と「ドラム素材」で挙動が変わります。[PO–33公式ガイド](https://teenage.engineering/guides/po-33/en)

これを4トラック構成へ落とすと、各トラックに固定役割を与えるのではなく、再生方式を選べる設計が合います。

| PLAY AS | 録音の扱い |
|---|---|
| TAPE | 録音をそのままループ再生 |
| KEYS | 音階を付けて演奏 |
| SLICE | 自動分割してパッド演奏 |
| VOICE | Pitch／Formantで声を再合成 |

初期状態は4トラックすべてTAPEです。録音後、必要なトラックだけ別方式へ切り替えます。元録音は常に保持し、変換は非破壊にします。

選択中のトラックには4つだけ操作を出します。

- TAPE：START / END / SPEED / DIRECTION
- KEYS：ROOT / RANGE / ENVELOPE / FILTER
- SLICE：CHOPS / OFFSET / ENVELOPE / PITCH
- VOICE：PITCH / FORMANT / START / SPEED

これなら画面上のノブ数を増やさず、同じ4ノブがモードに応じて意味を変えます。

重要なのはVOICEの初期値です。Neutralを標準にし、話者の輪郭を残します。Robot、Noise、Vocoder、Synth系は意図的に選んだ場合だけ使えるようにします。以前の「声を入れたらノイズになる」問題を繰り返さないためです。

OB–4からは、時間を指で掴んでループ化する感覚だけ採用できます。ただし、公式の常時ローリング録音は採用しません。[OB–4公式ガイド](https://teenage.engineering/guides/ob-4)

このアプリでは必ずユーザーがRECを押して録音し、録音済み素材に対してのみ「LOOP FROM PLAYBACK」を実行します。

したがって演奏画面は、

- 4トラックは継続再生
- 1トラックを選択
- PLAY ASを選ぶ
- 中央領域が鍵盤またはスライスパッドへ変化
- KAOSSは引き続きマスターFX

という構造がよさそうです。これで「4トラック録音機」のまま、録った声をあとから楽器にできます。

## 原文2 — OP–1 fieldから導いた共通時間軸と合成波形

OP–1 fieldを4トラックとして見ると、重要なのは「4本の独立したルーパー」ではなく、4トラックが同じテープ時間を共有している点でした。

公式ガイドでは、共通の再生位置・速度・ループ範囲に対して、各トラックのテイクをLift／Drop／Splitします。さらに、指定ループ内の4トラックをまとめて持ち上げるLift Allと、1トラックへ焼き込むMerge Dropがあります。[OP–1 field公式ガイド](https://teenage.engineering/guides/op-1)

これをアプリへ接続すると、合成波形は「完成した音声ファイル」ではなく、4トラックを束ねて時間を操作する面にします。

### 合成波形を直接触る

| 操作 | 動作 |
|---|---|
| タップ | その時間へ移動 |
| 横ドラッグ | 音を聴きながらスクラブ |
| 波形上を範囲ドラッグ | 4トラック共通のループ範囲を作る |
| 選択範囲を長押し | GRAB。範囲を一時的に掴んで反復 |
| GRAB中に左へ払う | 4トラックを同期したまま逆再生 |
| 指を離す | 元の時間軸へ復帰 |

ここで実際の4トラック音声を合成・破壊しません。合成波形に作られるのは、4本を束ねた「時間範囲への参照」です。

これなら、

- 声のトラック
- SLICE化したトラック
- 通常のループ
- 長さの違う環境音

が混在しても、時間位置を失わずまとめて演奏できます。

### 個別トラックを触る場合

選択したトラックの細い波形には、編集を4つだけ置きます。

`SPLIT　LIFT　DROP　UNDO`

- SPLIT：指した位置でテイクを分割
- LIFT：選択範囲を持ち上げ、元位置を空ける
- DROP：現在位置へ置く
- UNDO：直前の録音・移動・分割を戻す

OP–1 fieldも2026年4月の1.7.0でTape Undoを追加しています。また1.6.0ではLift／Drop後のクロスフェードが追加され、その後もループのポップ音や位置ずれが修正されています。[OP–1 field更新履歴](https://teenage.engineering/downloads/op-1/field)

ここからアプリ側には、編集点へ自動的にごく短いマイクロクロスフェードを入れます。画面上には出しません。

### MASTER WAVEとKAOSSの分離

同じ中央領域を、上部の2ボタンで切り替えます。

- `TAPE`：波形の時間を直接操作
- `FX`：KAOSSマスターエフェクト

FXへ切り替えても合成波形は背景に残します。ただし、この状態のX軸・Y軸はエフェクト操作です。時間移動は起こしません。これでスクラブとKAOSS操作の衝突を防げます。

### 採用しないもの

OP–1のMerge Dropは常用機能にしません。4トラックを1本へ焼くと、後から声だけ調整できなくなるためです。

代わりに`BOUNCE COPY`として隠し、実行しても元の4トラックを残します。空いているトラックがある場合だけ、選択範囲の合成音を新しいテイクとして複製します。

現時点の4トラック構造は、

- 4本は共通時間軸
- 合成波形は4本を束ねた演奏面
- 個別波形は素材編集面
- KAOSSは合成後のマスター処理
- すべての切断点に自動クロスフェード
- 録音・編集はUNDO可能

まで具体化できました。

## Deep Research全文（会話出力の原文）

今回、前案から一つ変えます。

合成波形の操作結果を直接オーディオへ焼くのではなく、4本の上に重なる「PERFORMANCE TAKE」として記録します。これは第5トラックではなく、再生位置・ループ長・逆転・KAOSS座標だけを持つ操作記録です。

Teenage Engineering製品を横断すると、次の型が反復されています。

| 製品 | 指で試す | 結果を残す |
|---|---|---|
| OP–XY | Punch-in FXを押している間だけ適用 | REC中なら専用FXトラックへ記録 |
| EP–133 | ループを作り、位置と長さをリアルタイム変更 | RECを押した操作だけパターンへ記録 |
| OB–4 | ループ位置をテンポ同期で滑らせる | 明示的な保存操作 |
| TP–7 | リールへ触れて停止・スクラブ | 録音・編集として明確に分離 |
| OP–1 field | Reverse／Chopなどを演奏 | Mixdown操作で演奏結果を録音 |

OP–XYは、Punch-in FXを一時的に演奏でき、録音時だけ専用トラックへ残せます。[OP–XY公式ガイド](https://teenage.engineering/guides/op-xy/auxiliary)

EP–133は、ボタンを保持した時間でループを作り、位置をテンポ同期で移動できます。またフェーダー操作はRECとの組み合わせで記録されます。[EP–133 Loop](https://teenage.engineering/guides/ep-133/functions)・[EP–133録音](https://teenage.engineering/guides/ep-133/play-and-record)

### 合成波形の演奏操作

再生中に合成波形へ触れると、指の位置から一時ループを掴みます。

| ジェスチャー | 結果 |
|---|---|
| 1本指で触れ続ける | GRAB／一時反復 |
| 左右へ動かす | ループ位置を滑らせる |
| 上へ動かす | ループを短くする |
| 下へ動かす | ループを長くする |
| 2本目の指を置く | 逆再生 |
| 全指を離す | 通常再生位置へ復帰 |

長さは段階式にします。

`1 BAR → 1/2 → 1/4 → 1/8 → 1/16 → GRAIN`

GRAINは最小領域ですが、単独の発振器にはしません。必ず録音された音の一部分を反復するため、入力がなければ鳴りません。

### AUTOとRAW

OB–4はBeat Matchを自動／RAWで切り替えられ、ループ位置の移動はテンポ同期します。[OB–4公式ガイド](https://teenage.engineering/guides/ob-4)

これを次のように限定して採用します。

- `AUTO`：拍を取得できた録音。移動位置と長さを拍へ吸着
- `RAW`：声・環境音・不定形演奏。波形上の実時間をそのまま操作
- 録音音声そのものへ自動補正はかけない
- 拍検出が失敗しても録音・再生は止めない

AUTOは初期録音を勝手に切ったり、テンポへ引き伸ばしたりしません。指の着地点だけを補助します。

### PERFORMANCE TAKEの記録

通常の波形操作は、指を離せば消えます。

`REC`を押している間だけ、以下を記録します。

- GRAB開始・終了
- ループ位置
- ループ長
- 正転／逆転
- KAOSSのX／Y
- FXプリセットの切り替え

記録後は合成波形の上へ細い赤線を表示します。赤線をタップすると、その操作だけMute／Deleteできます。4本の音声は一切変更しません。

KAOSSも同じ規則です。

- 指で触るだけ：一時的
- REC中に触る：PERFORMANCE TAKEへ記録
- 自動記録：なし

### 録音経路を常に表示する

OP–1 fieldは入力元、入力ゲイン、録音閾値を独立して選び、Sound Path画面では経路上の重要な値がゼロの場合に警告を出します。[OP–1 field公式ガイドPDF](https://assets.teenage.engineering/_img/69f248938d433104c4dd1846_original.pdf)

アプリ上部には常に実経路を出します。

`iPHONE MIC → PRE → T1 → MASTER → OUTPUT`

状態表示は分けます。

| 表示 | 意味 |
|---|---|
| INPUT ON/OFF | 音声入力が接続されているか |
| MON ON/OFF | 入力音を出力へ返すか |
| REC READY | 選択トラックへ録音可能か |
| REC | 実際に録音中か |

INPUT OFFならRECを押しても無音録音を開始せず、`INPUT OFF`を表示します。MON OFFでも録音は可能です。

TP–7は録音状態を赤いランプと回転するリールの両方で示し、リールそのものがスクラブ・停止・視覚フィードバックを兼ねます。[TP–7公式製品ページ](https://teenage.engineering/products/tp-7)

こちらも録音中は、

- RECボタンが赤い
- 対象トラック全体が赤くなる
- 合成波形の記録位置が動く

の三箇所で示します。

これで4トラックは音声素材として保護したまま、合成波形を一つの楽器として演奏でき、演奏を残すかどうかだけは必ず人間がRECで決められます。

## 2026-08-28 起動不良の報告と修正

ユーザーから「マイクが起動しなかった」「インターフェースがださい」と報告があった。

実装を再点検したところ、配布した `index.html` が `performance-take.mjs` を外部モジュールとして読み込む構造になっていた。単体HTMLとして開く経路では、この兄弟ファイルの読込み失敗によってスクリプト全体が開始せず、マイク起動ボタンも動作しなくなる実装上の欠陥があった。報告された環境で同じ失敗を実機再現したわけではないため、これを唯一の原因とは断定しない。

修正内容：

- Performance Takeの実行コードをHTMLへ内包し、単一ファイルで起動する構造へ戻した
- マイク取得はユーザーが `START MIC` を押したときだけ `getUserMedia` を呼ぶ
- 発光する円形コントロールとガラス調パネルをやめ、4本のトラックを矩形ストリップとして並べた
- 合成波形を中央、マスターを右に置き、録音対象と出力経路を読み取りやすくした
- 縦画面を遮断するオーバーレイを撤去し、縦画面でも操作面を表示する

静的テストでは外部モジュール依存がないこと、マイク起動が明示的なクリックに結び付いていることを検証する。実機のブラウザにおけるマイク許可、録音、音声出力、最終的な視覚品質は未検証であり、実機確認が残る。

## 2026-08-28 第二回実機報告 — 押せるが録音されない

HTTPSでHTMLを実行できる状態にした後、ユーザーから「押せただけ／録音されない」「teenage enginneringはこんなダサいものつくらない」と報告があった。したがって、第一回修正版は操作可能な表示までしか確認できず、録音機としては失敗である。

旧画面には次の問題が残っていた。

- トラック面そのものを押すと録音が始まる隠れた状態機械で、RECが見えなかった
- 入力接続、録音中、録音完了、再生の違いが弱かった
- iPhone Safariでの録音取得を非推奨の `ScriptProcessorNode` だけへ依存していた
- 退役したKAOSS面を残し、4トラック録音機の中心を曖昧にした
- 黒背景、発光、ガラス調という汎用オーディオUIで、Teenage Engineering製品の操作と表示の直結を再現していなかった

第二回修正版では旧UIを継承せず、次へ置き換えた。

- 4トラックそれぞれへ常時表示の `REC / PLAY / STOP / ×` を配置
- 入力は独立した `INPUT ON`、録音は各トラックの `REC` として分離
- 録音中はトラック外周、色、文言を同時に変える
- 実際に取得した音声サンプルだけから波形を描画
- `AudioWorkletNode` を第一経路とし、利用できないSafariでは `ScriptProcessorNode` へフォールバック
- KAOSS、円形発光、半透明ガラス面を除去
- 横画面と縦画面を別レイアウトとして保持

参照した公式上の根拠は、OP–1 fieldの4トラック・テープ構造、TP–7の録音と編集操作の直結、EP–133 K.O. IIの明確な機能別操作面である。製品外観の模写ではなく、操作単位と表示単位を一致させる原則だけを採る。

この段階でも実機録音の成功は未確認である。静的構文、録音経路、状態遷移、Git保存、HTTPS配信一致を検証した後、ユーザー実機で入力メーター、録音時間、実波形、再生音の順に確認する。
