# 音楽的再現を目標とする検証仕様と初回精度監査
日付: 2026-09-07 UTC

ユーザー要求: 「検証精度をあげてほしい 音楽的に再現できるくらい」。
共通方針 main の research/music-analysis/SOURCE_POLICY.md（blob e1b94026ffc5c9fb56d14c92ec5695698a6fdcc0）および README を取得して適用。Shazam→Apple preview と公式Bandcampの経路は保持する。既存の方法逸脱・保存事故の記録は撤回しない。

## 到達目標
測定値の列挙から、短い区間の演奏・打ち込み仕様を作り、その仕様だけから作った再現音を原音と比較する工程へ進める。これは今回達成済みの宣言ではない。
最初の対象はMetamorphosesの570–660秒。拍子と小節頭が未確定なので「何小節」と先に決めない。まず安定区間を選んで拍を検証し、その後4–8小節程度へ切り出す。

| 必要な成果 | 記録内容 | 採用に必要な検証 |
|---|---|---|
| 拍・テンポ地図 | 絶対時刻、拍候補、局所テンポ、拍子・小節頭の別候補 | クリックと原音の照合、倍半テンポ比較、区間をずらした安定性 |
| リズム譜・MIDI | パート別打点、休符、アクセント、フラム、連打、拍からのずれ | 原ミックスへの戻し照合、見逃し・余分な打点の評価 |
| 音高と和声 | 音名、オクターブ、音長、ベンド、ボイシング候補 | 倍音・打楽器共鳴との区別、複数音の取りこぼし、再合成比較 |
| 音色の再現仕様 | 発音源候補、包絡、フィルター、変調、空間処理 | 音高・音量を揃えた比較。重心一個で音色を決めない |
| 展開・演奏 | パートの出入り、反復長、変奏、各層のタイミング関係 | 前後区間を含む照合。機材操作・担当者の帰属は映像等との同期証拠が別途必要 |
| 比較記録 | 原音・再現音の同区間、残差、未再現要素 | 作成に使わなかった隣接区間でも成立するか確認 |

暫定の開発用目標: 主要な打点について許容差±15 msでprecision/recallを測る。ただし、人が照合した基準打点や信頼できる既知イベントがない実録音では正解率を報告しない。±15 msは今回定めた作業目標であり、普遍的な知覚閾値ではない。意図的な前後ずれは量子化して消さない。音高・音色・演奏の一致は打点一致から推論しない。
分離stemは二次証拠。モデル間合意だけを真値としない。再現音を作れても同一制作手法や同じ演奏操作を証明したとはしない。

## 今回実行した監査
元音源SHA-256: 428aaaf9341b3d453b977800c1aa65ef92979118483b84c8df0ce1d89e3078a2。
元バイト列を照合し、ffmpeg -xerrorで570–660秒を44.1 kHz stereoへ展開。既存の校正済み関数を変更せず、10・20・30秒窓、5秒刻みで計45窓を測定した。同一抽出器による感度検査であり独立手法の追認ではない。
データ: reconstruction-precision-results-20260907.json。実行器: reconstruction-precision-audit-20260907.py（既存source-main配置とevolution-audio配置を入力として要求）。

### 検出器の容量不足
既存onset_timesは最短ピーク間隔80 ms、フレーム約23.22 ms、hop約5.80 ms。hopは精度保証ではない。
117.45 BPM相当の人工パルスで:
- 四分音符あたり4打、間隔127.714 ms: 真値71打、検出71打。
- 四分音符あたり8打、間隔63.857 ms: 真値141打、検出62打。
これは単純な合成音の容量検査で、実録音の検出率ではない。従来のonsets/sは閾値依存候補密度として保持し、総打数、連打譜、奏者の手数へ転用しない。
次の抽出器は短間隔の複数発音と単音の二重検出を分ける既知イベント試験を通す必要がある。単に80 msを短くするだけでは採用しない。旧・新方式の同入力比較を保存してから解釈する。

### 10分付近の窓依存性
| 区間 | RMS dBFS | 上位周期候補（BPM換算、拍未検証） |
|---|---:|---|
|590–600秒|-12.16|93.12, 159.01, 65.42|
|600–610秒|-16.74|65.83, 93.12, 51.42|
|610–620秒|-17.11|91.47, 66.68, 114.84|
|620–630秒|-15.83|78.90, 77.71, 80.75|
|630–640秒|-11.58|120.19, 60.09|

30秒窓の「600秒で候補が変わる」は変化時刻を証明しない。590–600秒でも候補群が変わっている。600–620秒のRMS低下は短窓にも残るが、それをテンポ変更、ブレイク、奏者の操作と命名する証拠はない。620–630秒を含める比率により候補順位が変わる。旧結果を誤りとして削除せず、時間解像度の限界を追記する。

## 未達と継続点
今回行ったのは既存測定の解像度監査と再現検証の仕様化。聴取照合、拍・小節頭の確定、パート別採譜、分離、音高推定、MIDI・音色パッチ作成、再現音との比較は未実施。したがって音楽的再現精度には未到達。
次は短間隔打点検出の校正を行い、安定区間の拍候補を原音へ重ねて照合する。仕様→再現→比較→訂正を一巡させるまで「再現できる」と報告しない。
