# KNOWER研究 02――Shazamプレビューによる録音版／live band sesh版比較

- research-id: `20260831-knower`
- phase: `02-preview-comparison`
- 更新日: 2026-09-03
- 対象: `Overtime`、`Time Traveler`、`I'm the President`
- 取得経路: Shazam検索から返されたApple Musicカタログと公式30秒プレビュー
- 状態: `active / partial`
- 実装変更: なし

## 0. この更新で進んだこと

前稿の「録音版とlive band sesh版を比較する」を、まず正式カタログで同定できる30秒プレビューの範囲で実行した。

今回確認できた中心差は、単純な「録音版は電子的、ライブ版は生演奏」ではない。

1. `Time Traveler`は、録音版とライブ版で大きな音量輪郭をある程度共有しつつ、ライブ版では発音密度と高域の占有が減る。
2. `Overtime`は、プレビュー区間同士の大きな輪郭が一致せず、ライブ版の瞬間的な強弱差が大きい。
3. したがって、ライブ移植には少なくとも「輪郭を保ったまま関係を疎にする型」と「事件列そのものを再編する型」がある。

この結論は30秒プレビューの信号分析に限る。曲全体の形式、演奏者間の合図、正確な拍位置を確定するものではない。

## 1. 証拠区分

### 確認事実

Shazam検索から、次の正式カタログ項目と30秒プレビューを取得した。

| 曲 | 版 | Apple Music song ID | 全長 | プレビュー |
|---|---|---:|---:|---:|
| Overtime | `Life`録音版 | `1078024114` | 268.261秒 | 29.977秒 |
| Overtime | live band sesh | `1793615528` | 280.250秒 | 30.001秒 |
| Time Traveler | `Let Go`録音版 | `634974416` | 226.500秒 | 29.977秒 |
| Time Traveler | live band sesh | `1793615530` | 246.000秒 | 30.001秒 |
| I'm the President | `Knower Forever`版 | `1704417177` | 247.000秒 | 30.001秒 |

全長では、live band sesh版が録音版より`Overtime`で11.989秒、`Time Traveler`で19.500秒長い。長さの差だけでは、テンポ差、ソロ、反復追加、余韻、編集差のどれによるかは決められない。

### 計測結果

取得したAACプレビューをモノラル22.05 kHzへ変換し、同一条件で短時間フレーム分析した結果。

### 分析仮説

計測差から演奏機能を推定した部分。本人の意図、ミックスのステム、正式な採譜結果ではない。

### 未検証

- 各プレビューが曲全体のどの時点を切り出したか
- 二版のプレビューが同一セクションか
- Apple Music側のラウドネス処理とエンコード差
- 曲全体の停止、再突入、ソロ順、正確な小節数
- 各発音を担当する楽器の自動分離

## 2. 計測方法

比較を再現できるよう、今回の処理条件を固定した。

1. Shazamで曲名とアーティスト名を検索する。
2. 返されたApple Music song ID、全長、プレビューURLを記録する。
3. プレビューを22.05 kHz、モノラルPCMへ変換する。
4. 2048 sample窓、512 sample hop、Hann窓で短時間スペクトルを取る。
5. 次を算出する。
   - RMSの平均、標準偏差、90–10パーセンタイル差
   - スペクトル重心
   - スペクトル平坦度
   - 正のスペクトルフラックスによる発音候補数
   - 低域／中域／高域のエネルギー比
   - 1秒RMS輪郭
6. 二版の1秒未満RMS輪郭を標準化し、±3秒で最大相関を探す。

発音候補数は音符数ではない。子音、ドラムの複数成分、残響変化もピークになり得る。スペクトル重心も編成だけでなく、ミックス、EQ、歪み、AAC圧縮の影響を受ける。

---

## 3. 計測表

| 曲・版 | 発音候補/秒 | RMS変動幅 p90–p10 | スペクトル重心 | 平坦度 | 低域 20–200 Hz | 中域 200–2000 Hz |
|---|---:|---:|---:|---:|---:|---:|
| Overtime 録音版 | 5.88 | 17.06 dB | 3234 Hz | 0.5295 | 55.3% | 35.1% |
| Overtime live | 5.47 | 24.91 dB | 2555 Hz | 0.3864 | 48.7% | 49.3% |
| Time Traveler 録音版 | 6.05 | 11.37 dB | 3083 Hz | 0.5001 | 58.9% | 31.1% |
| Time Traveler live | 4.84 | 13.31 dB | 1723 Hz | 0.2771 | 63.2% | 35.0% |
| I'm the President | 5.37 | 10.40 dB | 1654 Hz | 0.2774 | 49.7% | 49.0% |

### 読み方

- `Overtime`のライブ版は、発音候補密度が録音版より約7%低い一方、フレーム単位の強弱差は大きい。
- `Time Traveler`のライブ版は、発音候補密度が録音版より約20%低い。
- 両曲ともライブ版のスペクトル重心と平坦度が低く、プレビュー内のエネルギーが高域全体へ広がる度合いが小さい。
- この差は「ライブ演奏は暗い音色」という一般則ではない。今回の該当抜粋で、電子的な高域層、歪み、ノイズ状成分、短い装飾が減った可能性を示すだけである。

## 4. `Time Traveler`――輪郭保持型の移植

### 計測

録音版とlive band sesh版のRMS輪郭は、ライブ版を約1.0秒ずらした位置で最大相関`r = 0.386`だった。

強い一致ではないが、両方に次の大きな推移がある。

```text
前景が強い状態
  -> 約10秒続く低エネルギー状態
  -> 再び強い状態
```

一方、ライブ版では発音候補密度が約20%少なく、スペクトル重心は約44%低い。

### 分析

これは、ライブ版が録音版の全レイヤーを再現するのではなく、セクションの大きなエネルギー輪郭を残し、その内部の発音と帯域占有を奏者へ再配分している可能性と整合する。

ここで保存されている候補は、個々の音色や音符ではなく次の三つである。

- 強状態から弱状態へ入る境界
- 弱状態が占める時間幅
- 強状態へ戻る方向

その内部では、ドラム、ベース、鍵盤がすべて同じ細分密度を持つ必要がない。

### 楽器設計への翻訳

`Time Traveler`型の操作は、シーンを丸ごと切り替えるボタンではなく、エネルギー輪郭を保持したRelation変化にする。

```text
preserve:
  sectionBoundary
  macroEnergyContour
  returnDirection

vary:
  onsetDensity
  bassDuration
  highBandOccupancy
  drumHarmonyPhase
```

演奏者が指を動かしたとき、曲の大きな進行方向を壊さず、誰が細分を埋めるかを変えられる構造が候補になる。

## 5. `Overtime`――イベント再編型の候補

### 計測

録音版とlive band sesh版のRMS輪郭の最大相関は、±3秒の探索で`r = 0.100`だった。二つの抜粋を同一のエネルギー輪郭として対応づける根拠は弱い。

ライブ版は録音版より発音候補密度が約7%低いが、RMSの90–10パーセンタイル差は7.85 dB大きい。

### 分析

今回のプレビューに限れば、ライブ版は単に音数を減らしただけではない。発音の総密度を大きく落とさず、弱い瞬間と強い瞬間の落差を拡大している候補がある。

これは前稿で立てた、停止、前景交代、再突入を第一級イベントとして扱う仮説と整合する。ただし輪郭相関の低さには二つの競合説明がある。

1. live band sesh版が事件列を実際に再編している。
2. Apple Musicの二つのプレビューが曲内の異なる箇所を抽出している。

現段階では2を排除できない。したがって「再編型」は有力仮説であり、確認事実ではない。

### 暫定イベント記法

正式採譜の代わりに、今後の全曲確認で埋めるイベント列の器を定義する。

```text
E = {
  t,
  boundaryType,     // beat, bar, phrase, free
  foregroundRole,   // voice, drum, bass, keys, sax, ensemble
  densityBefore,
  densityAfter,
  cutDepth,         // 0..1
  reentryPressure,  // 0..1
  confidence,
  evidenceSpan
}
```

`evidenceSpan`を必須にし、30秒プレビューから曲全体の事件列を捏造しない。

## 6. `I'm the President`――連続変化と場面イベントの分離

今回正式カタログで取得できたのは同一ISRCの録音版一種で、比較可能なライブ版はない。

30秒プレビューでは、発音候補密度は5.37/秒、RMS変動幅は10.40 dBだった。1秒単位のRMS範囲は3.57 dBに収まり、この抜粋だけを見ると大きな音量場面転換より持続的な高エネルギー状態に近い。

したがって、前稿の「ファンファーレ、合唱、全体イベントが統治状態を変える」という曲全体の聴取記述を、今回のプレビュー計測が実証したとは扱わない。

それでも設計上は、二種類の変化を分離しておく価値がある。

| 変化 | 入力 | 実行時点 | 状態への作用 |
|---|---|---|---|
| Relation morph | 継続移動、接触間距離 | 即時～短い平滑化 | 現在状態の一部を連続変更 |
| Scene event | 急な集合、離指、打撃 | 音楽的境界 | 複数機能を一回で不連続変更 |

曲全体の正式な場面列を得るまでは、`I'm the President`を仕様の証明ではなく、分離仮説を試す対象として残す。

## 7. 実装を伴わないマルチタッチ状態遷移仕様 v0.1

前稿のCarrier / Relation / Eventを、入力時間と実行時間の違いまで含めて具体化する。

### 7.1 三つの時計

| 時計 | 用途 | 典型入力 | 応答 |
|---|---|---|---|
| Gesture clock | 打撃、接触、移動の知覚 | tap、drag、spread | 即時 |
| Relation clock | 密度、音価、位相、結合率 | 継続接触 | 即時～短い平滑化 |
| Event clock | 停止、再突入、場面転換 | 集合、離指、急変 | 最短の安全境界 |

三つを一つの量子化へ押し込まない。打撃の手応えを待たせず、複数パートの切替だけを境界へ預ける。

### 7.2 状態

```text
State = {
  carrier: {
    phase,
    pulseConfidence,
    macroEnergyContour
  },
  relation: {
    onsetDensity,
    bassDuration,
    harmonyDuration,
    drumBassCoupling,
    highBandOccupancy,
    spatialTail
  },
  pendingEvent: null | Event,
  foregroundRole,
  pressure
}
```

### 7.3 遷移

```text
touchStart
  -> Gesture clockで即時応答
  -> Relation候補を開始

touchMove
  -> Relationを連続更新
  -> macroEnergyContourは既定では保持

rapidCluster / collectiveRelease
  -> Event候補を生成
  -> 最短の安全境界までpending

safeBoundary
  -> pendingEventを一回だけ実行
  -> 新Stateを現在状態として保持
```

### 7.4 二つの遷移型

#### 輪郭保持型

`Time Traveler`比較から得た候補。

- macroEnergyContourを固定する
- 発音密度と帯域占有を変える
- パートごとの音価と位相を独立させる
- 強／弱セクションの帰還方向は壊さない

#### イベント再編型

`Overtime`比較から得た候補。

- 現在密度を下げるだけでなく、落差を作る
- foregroundRoleを一回のイベントで交代できる
- cutとreentryを対として記録する
- 全曲証拠を取得するまで自動採用しない

### 7.5 予測可能性の条件

文脈依存を無作為にしないため、次を固定する。

1. 同じState、同じgesture、同じboundaryなら、同じ種類の結果になる。
2. 音高や細部が生成されても、密度、方向、役割交代は演奏者が予測できる。
3. pendingEventは画面または触覚相当の反応で受理を示す。
4. cut後のreentry条件を消失させない。
5. 4接触以上の仕様は実機検証まで確定しない。

## 8. 前稿からの認知更新

### 維持

- ライブ化は全レイヤーの再現ではなく、演奏機能の再配分である。
- 音ではなく関係を演奏対象にする。
- Carrier / Relation / Eventを分離する。
- 停止と再突入を第一級イベントにする。

### 更新

- 「レイヤーを減らす」だけでは不十分。ライブ移植には、輪郭保持型とイベント再編型を分けて考える必要がある。
- 高域占有の減少と発音密度の減少は別の軸である。
- 同じ曲名の二版でも、プレビュー区間が対応しているとは限らない。版比較には`evidenceSpan`が必要である。
- マルチタッチ仕様には、Carrier / Relation / Eventだけでなく、Gesture / Relation / Eventという実行時計の分離が必要である。

### 失効

- 30秒プレビューだけから`Overtime`全体の停止・ソロ・再突入順を確定できる、という扱い。
- `I'm the President`の場面イベント仮説を今回の信号計測で確認済みとする扱い。
