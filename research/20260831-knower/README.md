- 現在の問い: KNOWERがDAW的な高密度編集を生演奏へ戻す方法から、iPhoneマルチタッチ楽器へ何を移せるか
- 状態: `active`
- 更新日時: 2026-08-31

## 証拠区分

- **確認事実**: KNOWER公式Bandcampの作品・クレジット、公式YouTube、Louis ColeまたはGenevieve Artadi本人へのインタビューで取得できた内容。

## 1. 中心判断

KNOWERから採るべき中心は、超絶技巧、ファンクの音色、複雑なコード、奇抜な映像のどれか一つではない。

中心にあるのは、次の変換である。

```text
DAW内の高密度な編集
  -> 演奏に必要な機能だけを抽出
  -> ドラム、ベース、鍵盤、声、管楽器へ再配分
  -> セクションの切断、再突入、密度変化を人間同士で演奏
```

通常のルーパーは、完成した音声またはMIDIパターンを周期的に再生し、その上へ別素材を加える。KNOWERのライブ・バンドで重要なのは、同じ小節の保存量ではなく、各奏者が次の小節へ入るたびに関係を更新できることだ。

本プロジェクトへの仮の翻訳は次になる。

> 音は循環してもよいが、演奏判断まで循環させない。

これは現時点の設計仮説であり、製品仕様への採用は未決定。

## 2. 二人の役割をLouis Cole一人へ回収しない

### 確認事実

KNOWERはLouis ColeとGenevieve Artadiの共同体である。Artadiは結成初期について、自分が曲を書き、Coleがプロダクションを担う案から始まったと説明している。その後は、Artadiがソングライティング、セクション、器楽パートを作り、Coleが多くの楽器を演奏する場合が増えたが、役割は変化し続けている。

Artadiは自身の作曲について、LogicとMIDI鍵盤を使い、ドラムまたは和声、旋律、声、歌詞という順序で進めることが多いとも説明している。

『KNOWER FOREVER』では、曲ごとの作者表記がLouis Cole単独とCole / Artadi共作に分かれる。アルバム全体のproduction、mix、masterはCole。主唱はArtadiであり、曲ごとにSam Wilkes、MonoNeon、Jacob Mann、Rai Thistlethwayte、Paul Cornish、Sam Gendel、David Binneyらが参加する。

### 聴取分析

Coleは単に難しいドラムを叩くのではなく、合奏全体の切断点と再突入点を身体で提示する。ドラムは伴奏と指揮とリアルタイム編集を兼ねる。

Artadiの声は、周囲の情報密度に対して比較的短く、乾いており、反復可能な輪郭を持つ。複雑な背景の上で声まで過剰に装飾しないため、曲の同一性が残る。Artadiの役割を「Coleの演奏へ歌を乗せる人」と扱うと、曲のセクション、和声、旋律、言葉が担う構造を失う。

### 設計への含意

本プロジェクトでも、次を一つの自動伴奏器へ回収しない。

- 時間を切る機能
- 低音と打点を結合する機能
- 和声の方向を決める機能
- 曲の同一性を保つ短い輪郭

一人の演奏者が操作する場合でも、内部機能は独立したまま相互作用させる。

## 3. 時期ごとの変化

### 3.1 初期――宅録の内部に複数の音楽を同居させる

公式Bandcampで確認できる主要アルバム系列は次の通り。

| 年 | 作品 |
|---:|---|
| 2010 | `Louis Cole and Genevieve Artadi` |
| 2011 | `Think Thoughts` |
| 2013 | `Let Go` |
| 2016 | `LIFE` |
| 2023 | `KNOWER FOREVER` |
| 2025 | 4曲作 `some thingies` |

Artadiの回想では、『Think Thoughts』期にTim Lefebvreのファンク、David Binney周辺の奏者、Coleが学んでいた映画音楽・管弦楽法など、多数の影響が投入された。

### 3.2 `Let Go`――音色変化とドロップを作曲単位にする

Artadiは、ColeがSkrillexなどの電子音楽を発見し、プロダクションがより過激になったと説明している。同時に、二人は奇妙な和声や美学を残したまま、DJがクラブでかけられる接近可能性を持たせようとしていた。

聴取上、ここではコード進行の上にビートを置く上下関係が弱まり、音色変化、ブレイク、セクション切替そのものが曲の主要事件になる。

### 3.3 `LIFE`――高密度編集を一つの文法へ圧縮する

聴取分析では、以下が同時に働く。

- 細かい同期と意図的なずれ
- ベースとキックの複合リフ
- 短いヴォーカル句
- 突然の全休止
- 性格の異なるセクションの接着
- ポップな反復と拡張和声

重要なのは「難しいコードの上で長くソロをする」ことではなく、リズム、和音、音色、編成、曲構造を同じ速度で切り替えることにある。

### 3.4 2017年以降のlive band sesh――再現から機能移植へ

Artadiは、録音作品とデュオ演奏には大量の電子レイヤーがある一方、フルバンドではテクスチャを減らし、各奏者が固有の力を持ち込むと説明している。

聴取上、`Overtime (Live Band Session)` と `Time Traveler (Live Band sesh)` は、録音版の全レイヤーをそのまま鳴らす試みではない。ドラム、ベース、鍵盤、サックス、声へ、曲を成立させる機能を再配分している。

したがってライブ化は、音源の再現度を上げる工程ではなく、音源の情報密度を演奏者間の応答密度へ変換する工程と判断する。

### 3.5 `KNOWER FOREVER`――宅録空間に大編成を入れる

公式クレジットでは、生ドラム、複数ベーシスト、複数鍵盤奏者、サックス、ギターに加え、弦、金管、フルート、合唱が曲ごとに編成されている。

聴取上、大編成は常時鳴る豪華な背景ではない。セクション境界を破裂させる、一瞬だけ別の空間を出す、リズムを巨大化する、声とリズム隊だけでは作れない時間幅を作るために使われる。

## 4. 曲別分析

### 4.1 `Overtime (Live Band Session)`

#### 聴取できる構造

厳密な小節番号と拍子は正式総譜未取得のため固定しない。大きな機能の推移は次のように聴ける。

```text
歌と和声の提示
  -> 高密度グルーヴ
  -> 歌の再配置
  -> サックスの前景化
  -> 鍵盤の前景化
  -> 時間密度の縮小
  -> 高密度状態への再突入
```

#### 中心

高速状態と低速に感じる状態の差を、BPM表示だけで作っていない。

- 細分音符の量
- スネアとキックの着地点
- ベース音価
- 和音の持続
- 残響が占める時間
- 次のセクションへ向かうフィル

が同時に変わることで、異なる時間状態へ移る。

#### 設計仮説

単一の指移動を、単一エフェクト量ではなく、次の関係ベクトルへ写像する。

```text
timeState = {
  drumDensity,
  bassDuration,
  chordDuration,
  transientSharpness,
  spaceTail,
  reentryPressure
}
```

この写像を既存のKAOSS型Master XYへ戻さない。現在の音声へ一括エフェクトをかけるのではなく、次に生成・再生される各機能の振る舞いを変える。

### 4.2 `Time Traveler (Live Band sesh)`

#### 中心

大規模な場面転換より、共通パルス上でのアクセント、発音、音価の関係が時間感覚を変える。

16分音符相当の内部位置を抽象的に `P = {0..15}` と置く。これは正式な採譜結果ではなく、設計モデルである。

通常の固定ループは、周回 `n` と `n+1` で同じ発音集合を再生する。

```text
D[n+1] = D[n]
B[n+1] = B[n]
H[n+1] = H[n]
```

KNOWER的な関係操作としては、輪郭を残しながら各機能を別量だけ更新する。

```text
D[n+1] = transform(D[n], deltaDrum)
B[n+1] = transform(B[n], deltaBass)
H[n+1] = transform(H[n], deltaHarmony)
```

キック、ベース、鍵盤を同じ量だけ平行移動させず、先導、遅れ、保持を分ける。これにより、単純なBPM変更に依存せず、拍の現在位置が揺れる感覚を作れる。

#### 設計仮説

- 横方向: ドラムに対するベース／和声の位相関係
- 縦方向: 発音密度と残す着地点の選別
- 静止: 現在の位相関係を保持
- 急な方向転換: 次の安全な音楽境界で関係を反転

指を離した瞬間にプリセットの中央へ戻さず、その時点の関係を現在状態にする案を検証候補とする。

### 4.3 `I'm The President`

#### 確認事実

公式クレジット上の主要演奏者は次の通り。

- Genevieve Artadi: vocal
- Louis Cole: drums
- Sam Wilkes: bass
- Jacob Mann: keyboard
- Paul Cornish: keyboard / piano
- brass、flutes、choir、strings

作者表記はLouis Cole / Genevieve Artadi。

#### 聴取分析

ファンク、歌、ファンファーレ的な大編成、合唱、ピアノの前景化、激しい全体イベントが、一つの安定したテクスチャへ溶けず、異質な場面のまま接着される。

ここで大編成は、各トラックへ少しずつ厚みを足すレイヤーではない。曲全体の統治状態を一回で変える「場面イベント」として働く。

#### 設計仮説

現在状態を次で表す。

```text
S = {
  pulse,
  bassRelation,
  harmonyField,
  orchestrationDensity,
  spatialDepth
}
```

通常ジェスチャーは `S` の一部を連続変化させる。一方、全員ヒット、全休止、ファンファーレ、再突入は、現在状態から派生する一回的イベントとして扱う。

```text
event(currentState, gesture, musicalBoundary) -> nextState
```

録音済みファンファーレを再生するのではなく、現在の音階、リズム、音域から短い上昇型ヴォイシング、低音下降、ドラムフィル、全休止を生成できれば、同一操作でも毎回の音楽的文脈を保持できる。

### 4.4 `The Abyss`

#### 聴取分析

派手な場面切替より、MonoNeonのベース、Coleのドラム、Rai Thistlethwayteの鍵盤、Sam Gendelのサックスが作る深いポケットが中心になる。

KNOWERを高速、過密、突然のカットだけへ縮めないための重要曲。少ない事件でも、音価、低音の位置、和声の沈み方、サックスの余白が継続的に更新される。

#### 設計への含意

ジェスチャー量が少ない状態を「何も演奏していない」と扱わない。低密度状態でも、音価、タイム、余白、残響、低音位置を演奏対象として残す。

### 4.5 `Crash The Car`

#### 聴取分析

歌、ドラム駆動、ギター／鍵盤、大編成が、別々のショーケースとして並ぶのではなく、一つの加速へ統合される。

#### 設計への含意

セクション切替を常に不連続なカットにしない。複数パラメータが同じ方向へ累積し、臨界点で状態が変わる「圧力型遷移」も必要になる。

## 5. KNOWERの演奏文法

### 5.1 グルーヴは保存物ではなく再照準

基礎パターンが反復しても、次のいずれかが更新される。

- アクセント位置
- ゴーストノート
- キックとベースの一致点
- 全員が消える位置
- フィルの開始位置
- 次セクションへの助走
- 音価と残響の占有時間

同じ小節を複製しているのではなく、各周回で拍の重心を照準し直していると解釈する。

### 5.2 ドラムは指揮と編集を兼ねる

Coleのドラムは一定ビートの供給だけを行わない。

- セクション開始を身体で宣言する
- 他パートと同時に切断する
- 密度を短時間で最大化する
- ベースと結合して複合リフを作る
- ソロ中も曲の時間輪郭を保つ

本プロジェクトでは独立DRUMを維持しつつ、他の4トラックまたは生成機能との関係を明示接続できる必要がある。

### 5.3 声は高密度状態の固定点

声に相当する機能を必ず歌唱合成にする必要はない。高密度状態でも曲の同一性を保持する短い輪郭として抽象化できる。

候補:

- 短い旋律輪郭
- 特徴的な一音色
- 反復する言葉または声断片
- 上声部の限定された運動

この固定点までランダム化すると、全パートが変化して曲の同一性を失う。

### 5.4 笑いが技巧の権威化を壊す

高度な演奏、和声、録音と、家庭用映像、安価なCG、身体的な冗談、唐突な字幕が同居する。これは単なる宣伝包装ではなく、技巧だけが作品の価値を独占する状態を壊していると分析する。

本プロジェクトでは、難しい内部モデルを画面上の権威的な専門用語やパラメータ列として見せない。簡単さは機能削減だけでなく、演奏者が直接結果を起こせる短い経路で作る。

## 6. マルチタッチ楽器への暫定翻訳

### 6.1 トラックではなく拘束条件を指で増やす

`一本指 = 一トラック` としない。指の本数は、現在の音楽へ同時に加える拘束条件の数として扱う。

例:

| 接触 | 候補機能 |
|---|---|
| 基準接触 | パルスまたは現在状態を保持 |
| 追加接触 | ベースとドラムの結合率を変更 |
| 別領域の接触 | 和声場または上声の方向を拘束 |
| 広がる複数接触 | 編成密度と音域を拡張 |
| 急な集合／離指 | 全員ヒット、停止、再突入候補 |

接触数だけで固定割当せず、位置、移動、接触順、現在状態を含めて解釈する。

### 6.2 三層の時間エンジン

固定ループ一層ではなく、次を分離する。

1. **Carrier**: 演奏が止まらないための基準パルスと音楽位置。
2. **Relation**: ドラム、低音、和声、素材再生の先導／遅れ／一致／音価。
3. **Event**: フィル、全休止、再突入、場面転換、圧力解放。

`Carrier`は録音済みドラムループである必要はない。時計と現在位置だけを保持し、発音内容は`Relation`と現在ジェスチャーから生成または選択できる。

### 6.3 イベント優先順位

同じ時点に複数命令が来た場合の暫定順位:

```text
STOP / CUT
  > SECTION EVENT
  > FILL / REENTRY
  > RELATION MORPH
  > SUSTAIN
```

これは安全な音響停止と音楽的明瞭さのための設計仮説。実装前に、指の誤認識、意図しない全停止、音量急増を検証する必要がある。

### 6.4 境界量子化を見せない

イベントを音楽的境界へ合わせる場合も、演奏者へ16ステップ編集画面を要求しない。

- 即時発音が必要な打撃は即時
- 複数機能を変える場面イベントは最短の安全境界
- 遅延中も視覚または触覚相当の反応で受理を示す
- 境界待ちを録音済みループの継ぎ目へ限定しない

境界候補は拍、フレーズ終端、無音、ゼロクロス、現在のPerformance Take文脈から決める。

## 7. 採用候補

以下は研究上の採用候補であり、`integration/`へ未反映。

1. **関係を演奏する**
   - 音符またはループ選択より先に、ドラム、低音、和声、空間の関係を操作する。
2. **毎周再生成する**
   - 同じ音声を複製せず、輪郭と拘束条件から次周を再構成する。
3. **全休止と再突入を第一級イベントにする**
   - ミュートボタンやエフェクトではなく、演奏行為として記録する。
4. **低密度状態も演奏として保持する**
   - 音数が少ないときは音価、余白、残響、低音位置を操作対象にする。
5. **Performance Takeへ状態変化を記録する**
   - 最終音声だけでなく、関係ベクトルとイベントを同じ時間軸へ記録する候補。
6. **内部複雑性を短い身体経路へ圧縮する**
   - 画面へコード名、拍子、16ステップ、全パラメータを常設しない。

## 8. 採用しない点

1. **KNOWERの曲、リフ、音色、声を模倣すること**
   - 研究対象は演奏構造であり、作風のコピーではない。
2. **超絶技巧を前提条件にすること**
   - ノンミュージシャンでも関係操作へ到達できる楽器という目的に反する。
3. **ライブ映像を根拠に、すべて完全生演奏だと断定すること**
   - 個別の再生素材、同期、補助信号、編集工程は未取得。
4. **多数のオーケストラ音源を常設すること**
   - 大編成の機能は場面イベントとして抽象化できる。音源数の増加を中心にしない。
5. **一ジェスチャーへ予測不能な変化を詰め込むこと**
   - 文脈依存と無作為を混同しない。同じ状態と同じ操作には学習可能な因果が必要。
6. **KAOSS型Master XYの復活**
   - KNOWER研究の関係ベクトルは、マスター音声への一括エフェクトではない。

```text

        +
```
