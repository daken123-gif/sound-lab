## 確認できた構造

### 1. THE PIPEは声をMIDIへ変換する装置ではない

THE PIPEは声、息、口で制御するダイナミックFXプロセッサ兼シンセサイザー。専用コンタクト・ボーカルマイクから入った音声信号を、各DSPアルゴリズムの励振源と制御源として同時に使う。

独立した外部音源へ音程情報だけを送るコントローラーではない。内部音響処理はマイクによる励振方法へ合わせて調整されている。通常の6.3 mm入力を採用しているため、外部マイク、アコースティック楽器、シンセ、ドラムマシンも入力できる。

完全に合成的なBASSDRUMでも、出力には生の声の要素が残り、発音の仕方へ敏感に反応すると設計者が説明している。

### 2. 入力部と演奏操作

- 専用コンタクト・ボーカルマイク
- マイク入力を有効化するタッチセンサー
- アルゴリズムごとに役割が変わるFXタッチセンサー
- 三つのパラメーター操作
- アルゴリズム選択
- 音量
- L/R出力
- 外部音声入力としても使用可能

公式ページでは交換マイクとして次の周波数傾向が示されている。

| マイク | 傾向 |
|---|---|
| STANDARD | 中域を強調した暖かい音 |
| FLAT | 中立で均衡した音 |
| BASSY | 低域を強調 |

専用マイクの存在は付属品ではなく、口腔、息、喉の近接した振動を取り、空間の反射やスピーカー出力から分離するための音響設計の一部。

### 3. 電気仕様

## 12アルゴリズムの発音原理

### ORPHEUS — 声で二つの仮想共鳴体を鳴らす

THE PIPE開発の出発点になったアルゴリズム。声が二つの仮想共鳴体を励振し、ノブで共鳴体の寸法と減衰を変える。

共鳴体の長さへ特定の波長関係が成立した周波数だけが強く残る。マニュアルでは、この関係からペンタトニックな音程集合が生じると説明される。

重要なのは声のピッチを正確に追跡して別の発振器を鳴らすことではない。声に含まれる広い周波数成分のうち、仮想物体が鳴れる成分を選び、共鳴によって音程感を発生させる。

### FILTERRA — 声量で動く共振フィルター

入力音量とFREQ操作に応じてフィルター周波数が変化し、共振量も動的に変わる。後段にリバーブを持つ。ドゥドゥクとシンセの中間のようなリードから、打撃的な音やノイズまで作る。

ここでは声量が単なるVCAではなく、音色の中心周波数と共振状態へ入る。

### SYNTH — 声を保ったシンセリード

動的ローパスフィルター、調整可能なカットオフ、オクターバー、リバーブ／ディレイを組み合わせる。声の連続性を残しながら、電子的なリードへ寄せる。

### REVERB — 空間と歪みで声を変形

リバーブ、調整可能なディストーション、ディレイの組合せ。声を別のトリガーへ変えるより、元の声の時間、密度、非線形性を拡張する。

### MADELAY — 読出し点が跳ぶディレイ

ディレイの読出し点が記憶内の別位置へリズミカルにジャンプする。TEMPOでジャンプ速度を調整でき、外部ビートへ耳で同期できる。

通常の固定タップ・ディレイではなく、一つの声の断片から時間的なフレーズを作る。

### PULSE — 声をパルス列へ変える

声をリズミカルでアルペジオ的なシンセ音へ変える。DECAYを短くすると分離した切れたパルスになり、長くするとパルス同士が重なり一つの大きな音へ近づく。

### BASSDRUM — 発声でキックを演奏する

TR-909に着想を得た合成キックを声で制御する。単純な固定サンプル再生ではなく、発音の強さとアーティキュレーションが結果へ残る。

### SWITCHABLE BASSDRUM — 生声とキックを指で切り替える

FXセンサーによって、直接マイク音と合成キックを切り替える。必要な位置だけ指でキックへ変え、自分でグルーヴを組む。

### BASSDRUM + SNARE — 口と指で二音色を演奏する

FXセンサーを押していないとスネア、押すとキックへ切り替わる。発声が時間情報を作り、指が楽器選択を担当する。

### OCTAVA — 声を複数オクターブへ広げる

複数のオクターブ・ピッチシフター、フィルター、ディレイの組合せ。

### GENERATOR — 声で内部音源と帰還を動かす

声で制御される音源、フィルター、リングモジュレーション、動的フィードバックを持つディレイを組み合わせる。入力音を加工する層と、入力によって内部生成音を動かす層が同居する。

### HARCHO — 極端なデジタル破壊

三種類のデジタル・ディストーション、ディレイ／リバーブ、ローパスフィルターを組み合わせた最も極端なアルゴリズム。

## THE PIPEの中核原理

### 声を四種類の情報として同時に使う

```
生音       -> 声そのものの質感
包絡       -> 音量、共振、減衰、キック強度
過渡       -> キック／スネア／パルスの開始
スペクトル -> フィルター、共鳴体、リング変調の材料
```

ピッチだけを抽出して声を捨てない。発声の雑音、息、子音、唇の破裂、喉の摩擦まで演奏情報として残す。

### 身体の役割を分割する

```
口・喉・息 -> 音の発生と連続変化
片手       -> 入力を開く
もう片手   -> FX、楽器切替、構造変化
三ノブ     -> 演奏前／演奏中の大きな音響範囲
```

この構造により、画面上で多数の小さなパラメーターを操作せず、呼吸と指の時間関係で演奏できる。

## iPhoneへ再構成する仮説

以下はTHE PIPEの公開仕様そのものではなく、iPhone向け設計仮説。

### 1. 音声解析を目的にしない

主経路は音声→MIDIではなく、音声をそのままDSPへ入れる。

```
iPhone mic
 -> input conditioning
 -> dry voice bus
 -> envelope / onset / noisiness extraction
 -> selected voice-synth engine
 -> blend
 -> safety limiter
 -> loop track input
```

補助的に抽出する値:

- 高速包絡: 子音、破裂音、キック開始
- 低速包絡: 息の強さ、リードの抑揚
- onset: パーカッションのトリガー
- periodicity: 歌声／息／ノイズの判別
- spectral centroid: 明るさとフィルター駆動
- zero-crossing / pitch confidence: 安定した発声時だけ音程補助
- input crest factor: 破裂音と持続音の分離

ピッチ検出が失敗しても音が止まらない設計にする。

### 2. 最初は4エンジンへ圧縮する

12モードをそのまま画面へ並べない。発音原理の差を保った4種類から始める。

| 仮称 | THE PIPE参照 | 役割 |
|---|---|---|
| BODY | ORPHEUS | 声で仮想共鳴体を鳴らす |
| LEAD | FILTERRA + SYNTH | 声量で共振と明るさを演奏する |
| PULSE | PULSE + MADELAY | 発声をリズムと断片へ変える |
| DRUM | BASSDRUM 3種 | 発声と指でキック／スネアを演奏する |

OCTAVA、GENERATOR、HARCHO、REVERBは独立モードにせず、各エンジンの変形先または後段処理として検証する。

### 3. UIは声を演奏するための最小構造にする

横画面でも縦画面でも、基本操作は変えない。

- 中央: 大きな発声パッド。押している間だけ音声シンセ入力を開く。
- 左: BODY / LEAD / PULSE / DRUM。
- 右: FXタッチ領域。押す、なぞる、二本指で音響状態を変える。
- 下: `BODY`、`MOTION`、`SPACE` の三マクロ。
- 常時見える: 入力レベル、出力レベル、フィードバック警告。
- 録音は別操作。音声シンセを選んだだけで自動録音しない。

元のTHE PIPEと同じく、発声とFX操作は同時に行える必要がある。マルチタッチを前提にする。

### 4. コンタクトマイクとiPhoneマイクの差

THE PIPEのマイクは口に近い振動を取り、スピーカーからの空気音を拾いにくい。iPhone内蔵マイクは室内音、端末スピーカー、反射を同時に拾う。

したがって動作条件を分ける。

#### イヤホン／外部出力

- フルレンジのリアルタイム処理
- 長い共鳴と帰還
- ドライ音との自由なブレンド
- GENERATORやHARCHO型の高ゲイン処理

#### iPhone本体スピーカー

- 押している間だけ入力する
- 長い高ゲイン帰還を制限する
- DRUMと短いPULSEを優先する
- 出力上限を下げる
- 入力へ戻ったスピーカー音を再励振し続けないよう、エンジン別に帰還量を制限する

本体スピーカー環境でイヤホン時と同じ処理を行うと、THE PIPEの再現ではなく音響フィードバック機械になる可能性が高い。

## BODY / ORPHEUS最小DSP仮説

二つの仮想共鳴体を、複数モードを持つ共鳴バンクとして試作する。

```
excitation = hp(input) * envelope(input)

for resonator r in [A, B]:
    base = sizeToFrequency(size[r])
    for mode k:
        f = base * modalRatio[k]
        y[r] += resonantBandpass(excitation, f, decay[r], gain[k])

output = saturate(y[A] + y[B] + dry * dryMix)
```

重要な検証点:

- 固定した西洋音階へ量子化せず、共鳴関係から音程集合を作る。
- 母音だけでなく、息と子音が共鳴体をどう励振するかを見る。
- 声量で出力音量だけを変えず、共鳴の立ち上がりと飽和も変える。
- 共鳴が止まりきる前に次の発声を入れたときの相互作用を残す。

## LEAD / FILTERRA最小DSP仮説

```
fast = fastEnvelope(input)
slow = slowEnvelope(input)
brightness = spectralCentroid(input)

cutoff = baseFreq
       * exp2(envDepth * slow)
       * exp2(brightnessDepth * brightness)

resonance = clamp(baseQ + qDepth * fast, safeQMin, safeQMax)

wet = dynamicResonantLPF(input, cutoff, resonance)
output = wet + octaveLayer(wet) + shortSpace(wet)
```

声量でカットオフとQを同じ方向へ動かすだけでは暴れやすい。入力が強いほどQを一定点から抑える逆制御も比較する。

## DRUM最小DSP仮説

```
if onsetDetected(input):
    strength = onsetStrength(input)
    noisiness = inputNoisiness(input)

    kick = pitchEnvelopeOsc(
        startFreq = map(strength, 90, 180),
        endFreq = map(strength, 38, 55),
        decay = kickDecay
    )

    snare = bandNoise(noisiness, snareTone)

instrument = fxTouch ? KICK : SNARE
output = selectedTransient + shapedInputTransient
```

声の要素を消さないため、合成ドラムへ入力過渡の短い成分を混ぜる。

## Field Looperへの接続

```
iPhone mic
 -> THE PIPE型VOICE SYNTH
 -> monitoring bus
 -> selected one of 4 audio tracks
 -> normal loop record/play
 -> master processing
```

VOICE SYNTHはルーパーの代替ではなく、録音前の楽器。4音声トラックの録音／再生規則を変えない。音声シンセを選択しても録音は始めない。

ドラム部へ直接統合もしない。DRUMエンジンの発音をドラムイベントとして利用するか、音声としてループへ録るかは後段で分ける。

## 採用する点

- 声そのものを励振源と制御源へ同時使用する。
- 歌唱の上手さではなく、息、子音、唇、喉、声量を演奏語彙にする。
- ピッチ検出が失敗しても鳴る。
- 生声の断片を合成音に残す。
- 発声と指のFX操作を同時に行う。
- 三つ程度の大きなマクロだけを見せる。
- 音声シンセと録音開始を分離する。
- 本体スピーカーとイヤホン環境を同一視しない。

## 採用しない点

- THE PIPEをボコーダー、オートチューン、声→MIDIへ縮めること。
- 12アルゴリズム名だけをコピーし、中身をプリセット差にすること。
- 声を捨てて、検出ピッチだけで通常のVCOを鳴らすこと。
- すべての発声を固定サンプルのトリガーにすること。
- 発声パッドを押した瞬間に録音も自動開始すること。
- iPhone本体スピーカーで無制限の長い帰還を許すこと。
- THE PIPE、TERRA、LYRA、PULSAR、COSMOS、FLUXを一つの巨大UIへ並べること。

## 次の研究

THE PIPE中心で最初に検証すべきなのはORPHEUS型BODYエンジン。

理由:

1. 声→MIDIではないことが最も明確に出る。
2. 息、子音、母音の違いがそのまま音色差になる。
3. ピッチ検出へ依存しない。
4. iPhoneマイクでも入力音を共鳴体へ直接入れられる。
5. THE PIPEらしさを、一般的なボイスエフェクトと最も早く区別できる。

UIより先に、録音済みの声と合成テスト信号で共鳴体の安定性を検証する。
